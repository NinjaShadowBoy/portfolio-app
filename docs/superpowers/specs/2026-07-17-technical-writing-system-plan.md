# Technical Writing System — Implementation Plan

**Date:** 2026-07-17  **Source spec:** `2026-07-17-technical-writing-system-design.md`

Generated by the understand→plan workflow (5 code maps + synthesis), then owner-reviewed.

## Summary

Dependency-ordered implementation plan for the Technical Writing System across two repos. 28 tasks in five tracks: Backend feedback reshape (Go/sqlc), Build pipeline (Node markdown compile + prerender wiring), Routing/i18n/nav, Design-system/shared-UI, and Feedback/rating-removal. Key sequencing constraints: (1) the backend compile chain migration->sqlc->{dto,service,handler}->tests must be serialized on the generated-model change; (2) the content-build script must emit the typed manifest before ArticleDataService, prerender params, and detail/index components can consume it; (3) rating.service.ts can only be deleted after all three importers (project-data.service, project-detail, profile) drop their references. Shared-file contention is limited: package.json (BP1 deps + BP3 scripts) must serialize; every other shared file (angular.json, app.routes.ts, app.routes.server.ts, header.component.html, styles.css, project-detail.*, project-data.service.ts, profile.*) is touched by exactly one task each and is therefore parallel-safe against all others. Critical spec correction carried into the plan: getPrerenderParams enumerates SLUGS ONLY (lang is the dual-locale build, not a route/prerender axis) despite the spec's 'slug x lang' wording; routes are 'articles'/'articles/:slug' with NO :lang param. Frontend feedback wire contract (type + articleSlug, nullable projectId) must be agreed with the backend track before FB1/BE3 finalize.

## Owner rulings on open questions

1. **Article routes: eager-imported** (match repo; no lazy precedent).
2. **getPrerenderParams: slugs only** (per-locale build covers en/fr).
3. **Legacy comment backfill type: `critique`** (closest to a generic comment).
4. **articleSlug validation: non-empty + format (length/charset)**, no DB existence check.
5. **Keep Project DTO averageRating/totalRatings dormant** — remove only UI, no backend contract change.
6. **Canonical chip: primary-100/700, radius-6** variant.
7. **Add RSS autodiscovery `<link>` to index.html: YES** (overrides plan default-off).
8. **/fr sitemap+rss duplication: acceptable** with root canonical (minor follow-up).

## Remaining open questions (from synthesis)

- Lazy vs eager article route components: spec §3/task says 'lazy' but the repo has zero loadComponent precedent and every route eager-imports. Plan defaults to eager (RT1) to match the repo and keep the prerender/hydration flow proven. Needs owner sign-off before deviating.
- getPrerenderParams axis: the spec literally says enumerate 'every published slug × lang', but this repo's i18n is per-locale subPath builds — the correct implementation (RT2) returns SLUGS ONLY and lets the dual-locale build cover en/fr. Confirm the spec author accepts this correction (enumerating slug×lang would produce broken/duplicated prerender routes here).
- Default `type` for legacy comment rows: migration backfills existing project comments as 'critique'. Confirm that is the intended semantics (spec names the three types but no default).
- articleSlug trust boundary: articles have no DB row, so the backend cannot existence-check a slug. Decide accept-any-non-empty vs format validation (length/charset). Plan currently validates non-empty + optional format only.
- Do the projects endpoint / Project DTO still return averageRating & totalRatings? Plan keeps Project.averageRating/totalRatings fields dormant (removes only the minRating UI filter) to avoid backend contract drift — confirm with the backend track whether those fields are still emitted.
- Canonical tag/chip choice: two divergent chip styles exist (project-card primary-100 radius-6 vs project-detail surface-brand radius-25). Plan (DS1) consolidates to the primary-100/700 radius-6 variant — confirm that is the desired canonical look.
- RSS autodiscovery: should index.html get a <link rel=alternate type=application/rss+xml> tag? Not included by default (index.html is hand-tuned) — confirm if desired.
- Sitemap/RSS duplication under /fr/: locale asset copying puts sitemap.xml/rss.xml at both / and /fr/. Plan treats the /fr copies as harmless with root canonical — confirm acceptable, or add an explicit exclude.
