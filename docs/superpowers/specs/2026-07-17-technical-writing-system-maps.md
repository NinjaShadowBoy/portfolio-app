### Patterns to follow
- Lang = build-time locale via @angular/localize `subPath` (en='' at root, fr='fr'), NOT an Angular route param. There is exactly one set of routes; the app is compiled once per locale and routerLinks resolve against the per-locale baseHref. Any spec text saying '/:lang/...' or 'slug × lang' must be read through this lens.
- Routes are flat and EAGER-imported (top-of-file `import` + `component:` in app.routes.ts). Parent-with-children shape used for detail pages: `projects` → `''` + `:id`. Mirror exactly for `articles` → `''` + `:slug`.
- Route params read reactively: `toSignal(route.paramMap.pipe(map(p => p.get('id'))))`, then `computed()` to derive the model. Mirror with `'slug'`.
- Index→detail links use array routerLink form `[routerLink]="['/projects', id]"`; plain nav links use string form `routerLink="/home"`. Neither includes a lang prefix.
- i18n template marking: `i18n="<meaning/description>@@<stableCustomId>"` on element text, `i18n-<attr>` for attributes (e.g. `i18n-title`). Every string gets an explicit `@@id`.
- i18n TS marking: `$localize\`:@@id:Default text\`` — global, no import (polyfill `@angular/localize/init` + src/types/localize.d.ts).
- Nav is duplicated across a desktop list and a mobile list in one template; every nav change must be made in BOTH, and mobile anchors additionally call `(click)="toggleMenu()"`.
- Styling: reuse existing classes on nav links — `class="link liquid-glass"`, `routerLinkActive="active"`, `ariaCurrentWhenActive="page"`; no new CSS needed for the nav entry (per CLAUDE.md DRY rule).
- Language switch is a hard navigation (`window.location.assign`), intentionally reloading so the correct locale bundle loads — not an in-app router navigation.

### Patterns to follow
- Standalone components only (standalone: true, explicit imports array); no NgModules. selector app-*; templateUrl/styleUrls in a 4-file folder (ts/html/css/spec) under shared/ui or features/*.
- State via Angular signals: signal()/computed(); async subscribed with .pipe(takeUntilDestroyed(this.destroyRef)) and finalize() to reset isSubmitting flags. inject() for DI (no constructor params). private destroyRef = inject(DestroyRef).
- Route params -> toSignal(route.paramMap.pipe(map(...))); reactive data via effect() reacting to computed inputs (see project-detail.projectEffect). Angular 22 also uses rxResource in project-data.service.
- Two-way-ish template binding without ngModel: [value]="sig()" (input)="sig.set($any($event.target).value)". Buttons type="button" with (click).
- i18n mandatory: every user-facing string uses i18n / i18n-placeholder attributes or $localize`:@@stableId:Text`. New feedback strings need new @@ids.
- Styling DRY (CLAUDE.md): use design tokens (--surface-*, --text-*, --border-*, --btn-*, --color-danger/warning/*, --motion-*, --elevation-*, --focus-ring) and utility classes (.btn-primary/.btn-secondary/.btn-ghost, .input-field, .surface-*, .text-danger). No raw hex/rgba/box-shadow/duration where a token exists; component css holds only component-specific layout, promote reusable rules to src/styles.css.
- Ownership check pattern: identityService.identity()?.id === comment.userId gates edit/delete (project-detail.isMyComment, line 200).
- Services: @Injectable({providedIn:'root'}), inject(HttpClient), apiUrl built from environment.apiBaseUrl; return Observables typed with a *Dto interface exported from the service file.

### Patterns to follow
- Enum-as-CHECK, not a Postgres native ENUM type: existing columns (users.role, users.provider) use VARCHAR(N) NOT NULL DEFAULT '...' CHECK (col IN (...)). The comment `type` column should follow this exact idiom for consistency and easy Down migrations.
- Migrations are goose files numbered NNN_name.sql with `-- +goose Up` and `-- +goose Down` sections; run automatically at startup via goose.Up. Next file is 003. Down must reverse every Up statement (restore NOT NULL, drop columns/constraints/index).
- sqlc is source-of-truth-in-.sql: hand-edit db/queries/*.sql then `make sqlc`; never hand-edit internal/db/*.sql.go (they carry `// Code generated by sqlc. DO NOT EDIT.`). json tags are camelCase; query_parameter_limit is 8 so CreateComment keeps positional args.
- Nullable DB columns surface as sql.Null* in generated models and are mapped to pointer JSON fields in dto via helpers (dto.NullString, dto.Ptr). project_id going nullable changes db.Comment.ProjectID from int64 to sql.NullInt64 across all generated scans.
- Service validation returns sentinel errors (ErrBadRequest, ErrNotFound, ErrForbidden) that handler.writeError maps to HTTP codes; body validation lives in service (validateCommentBody), not the handler. Reuse ErrBadRequest for invalid type / bad target.
- Dual-URL convention: comments are already reachable via both /projects/:id/comments and /comments/project/:projectId (same handler, parseID tries multiple param names). Mirror this for articles if desired, but slug params need direct c.Param access since parseID is int64-only.
- Public participation routes sit under the EnsureIdentity `identified` group (anon-friendly writes); JWT-only routes sit under the `authenticated` group; admin under `admin`. New feedback writes belong in `identified`.
- Test convention: `go test ./...`; table-driven tests colocated as <pkg>_test.go. handler_test.go builds the real route tree with a nil service to assert routing/param/auth status codes; dto_test.go asserts struct mapping. There is currently NO service_test.go — service logic is exercised indirectly.

### Risks
- Making project_id nullable changes the GENERATED db.Comment.ProjectID from int64 to sql.NullInt64, which breaks every current scan/reference (comments.sql.go scans, service commentDTO/ListProjectComments/ListCommentsByProjectIDRow, ReassignCommentsToUser is fine). All must be updated after `make sqlc` or the build fails — a compile-time, not runtime, break.
- The one-target CHECK ((project_id IS NULL) <> (article_slug IS NULL)) must be enforced in BOTH the DB and the service; without the service pre-check a bad payload yields a raw 500 (constraint violation) instead of a clean 400 via ErrBadRequest.
- Adding `type NOT NULL DEFAULT 'critique'` backfills all existing project comments as 'critique'. Confirm that default is the intended semantics for legacy rows (spec lists critique/suggestion/feature_request but names no default).
- Existing UpdateComment/DeleteComment and ListCommentsByUserID/GetComment use SELECT */RETURNING * — they will silently start returning the new columns after regen; the scan structs change and must be re-mapped, and GetMyComments (ListUserComments -> commentDTO) now must handle article-targeted rows.
- Article slugs are validated only by the app/build (no DB table), so the backend cannot requireProject-style existence-check an articleSlug. Decide the trust boundary: accept any non-empty slug, or validate format (length/charset). Un-validated slugs let comments attach to non-existent articles.
- gin route registration is validated at startup (handler_test.go relies on this): adding /articles/:slug/comments near other wildcard routes risks a wildcard/static conflict panic — add a routing test case to catch it.
- article_slug VARCHAR length must accommodate real slugs (255 is safe); an index on it is needed for ListCommentsByArticleSlug to avoid a seq scan as comment volume grows.
- Frontend/API contract shift: Comment JSON gains `type`/`articleSlug` and `projectId` becomes nullable — the Angular feedback client must be updated in lockstep (separate area) or existing project-comment rendering may break on a null projectId.
